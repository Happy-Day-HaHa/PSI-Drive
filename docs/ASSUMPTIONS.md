# 가정 기록

실제 장비나 파일럿 데이터로 확인되면 항목을 갱신한다.

## 사양서 10장의 미확정 사항

| # | 항목 | 현재 기본값 | 확인 방법 |
|---|---|---|---|
| 1 | 압력센서 샘플링·ADC | 500Hz, 12bit | 시제품 펌웨어 사양 |
| 2 | 공통 클록 방식 | PPS + 공유 펄스 카운터 | 동기화 모듈 설계 확정 |
| 3 | 풋웰 카메라 | 30fps 기본, 60fps 지원 (`--foot-fps 60`) | 카메라 선정 |
| 4 | 점수 곡선 초기값 | 사양서 예시값 | 파일럿(운전자 20명, 200시간, 사건 1,000건) 후 재보정 |
| 5 | 업로드 방식 | 웹 업로드 | MVP 이후 검토 |

## 구현 중 정한 포맷 가정

1. **`sync_markers.csv`에 `stream`, `seq` 열을 추가했다.** 사양서는 `device_ts_us, marker_type` 두 열이지만 어느 클록의 값인지 구분이 필요하다. 실제 펌웨어가 다르면 어댑터에서 변환한다.
2. **동기화 모듈이 스트림마다 PPS 펄스 시각과 공유 카운터를 기록한다고 본다.** 항목 2가 다르게 확정되면 Phase 2의 1차 정렬을 바꿔야 한다.
3. **LED는 브레이크 탭을 감지한 뒤 고정 지연(기본 20ms)으로 켜진다.** 사람이 탭과 플래시를 동시에 맞출 수 없으므로 이 전제가 있어야 영상과 압력 마커를 교차 검증할 수 있다. 지연값은 매니페스트에 기록한다.
4. **`frame_idx`는 mp4 내 위치이며 드롭된 프레임에 번호를 주지 않는다.** 장비가 센서 프레임 카운터를 준다면 드롭 탐지가 더 정확해지므로 추가를 검토한다.
5. **IMU의 `ax`가 차량 전방 축이고 단위는 m/s², rad/s다.** 실제 장착 방향이 다르면 매니페스트의 축 정보로 변환한다.
6. **GNSS 단절 중에는 PPS도 끊긴다.** 카메라 모듈의 GNSS가 PPS 소스라는 전제다.
7. **장비 클록의 기점은 세션 시작 약 5초 전이다.** 드리프트 모델의 수치 안정성을 위해 UTC 절대값이 아닌 부팅 기준 값을 쓴다고 본다.

## 합성 데이터의 한계

- 차량 응답은 1차 지연과 순수 지연을 쓴 단순 모델이다. 경사, 타이어, ABS, 엔진 브레이크는 없다.
- 페달 신호는 구간 선형이라 실제 발 동작보다 onset이 뚜렷하다. 합성 데이터에서 낸 검출 정확도가 실제 성능을 보장하지 않는다.
- 영상은 도형 렌더링이며 영상 AI(Phase 8) 학습이나 평가에는 쓸 수 없다.
- 드라이버 반응 시간 분포(인지-해제 평균 520ms, 페달 전환 평균 320ms)는 임의의 값으로, 코호트 통계가 아니다.
- 프레임 드롭은 독립 무작위이며, 연속 드롭은 드문 경우로만 나타난다.
- 사양서 4.4의 지표 중 브레이크 커버링, 제동 부드러움, 가속 일관성, 재가속 지연은 정의가 Phase 3에서 확정되므로 아직 정답 JSON에 없다.

## 설정 파일에서 사양서에 없어 임의로 둔 값

`config/scoring_config.v1.yaml`에서 `# 가정` 주석이 붙은 값이다.

- 급가속 페달 상승률 임계값 300%/s
- 브레이크 커버링 최대 대기 400ms
- Sync `warning` 세션 가중치 0.5
- 곡선: 인지-해제 시간, 제동력 상승 시간, 급제동·급가속 빈도

## 화면

- `apps/web`의 점수, 알림, 주행 기록은 모두 샘플 데이터이며 측정값이 아니다.
- "이번 달 주행거리" 목표치(2,000km)는 레퍼런스 구성을 따른 예시다. 제품 지표로 둘지 결정이 필요하다.
- 레퍼런스의 "과속 비율"은 "페달 중첩"으로 바꿨다. 키트에 제한속도 데이터가 없어 과속을 측정할 수 없고, 사양서 지표에도 없다.
- 레퍼런스의 "매우 안전해요!"는 "습관이 좋아요!"로 바꿨다. 점수는 행동 지표이며 안전이나 과실을 판정하지 않는다.
- 레이더의 5개 항목(급가속, 급제동, 페달 중첩, 페달 전환, 제동 반응)은 화면용 묶음이다. 각 항목의 점수 산식은 Phase 4에서 확정한다.
- 맞춤 조언 문구는 예시이며, 운전 교육 관점의 검증을 받지 않았다.
